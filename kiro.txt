[보안 1] SESSION_SECRET 누락 시 서버 시작 차단
  파일: lib/auth.ts, .env.example
  문제: SESSION_SECRET 환경변수가 없어도 하드코딩된 기본 키로 서버가
        정상 실행됨 → 세션 토큰 위조 가능
  수정:
    - NODE_ENV=production 에서 SESSION_SECRET 없으면 process.exit(1) 호출
    - 개발 환경에서는 console.warn으로 경고만 출력
    - .env.example 에 SESSION_SECRET 항목과 생성 방법 주석 추가
      (node -e "console.log(require('crypto').randomBytes(32).toString('hex'))")

[에러처리 2] points.ts SQL Injection 위험 문자열 인터폴레이션 수정
  파일: lib/points.ts  (updateLastAchieved 함수)
  문제: base(날짜 문자열)를 쿼리에 직접 인터폴레이션 했음
        → `AND DATE(...) > '${base}'` 형태로 SQL Injection 위험 존재
  수정:
    - base 유무에 따라 쿼리 문자열을 분리 (조건부 인터폴레이션 완전 제거)
    - 파라미터 배열에 base를 바인딩하는 방식으로 변경
    - logs 쿼리, scrims 쿼리 모두 동일하게 수정

----------------------------------------------------------------
[성능] 파티 펑 시 Riot API getMatchIds 병렬 호출
  파일: app/api/party/route.ts  (awardPartyPoints 함수)
  문제: 각 클랜원의 puuid 별로 getMatchIds를 순차(for await) 호출
        → 5명 파티면 순서대로 API 호출을 기다려야 함
  수정:
    - Promise.all()로 모든 puuid의 getMatchIds를 병렬 호출
    - 에러 핸들링(.catch)은 기존과 동일하게 개별 적용
    - 결과를 Set에 합산하는 로직 유지
