================================================================
  LoL Clan Manager — DB 테이블 & 칼럼 설명서
  기준: lib/db.ts 전체 스키마
================================================================

──────────────────────────────────────────────────────────────
■ members  (클랜원 목록)
──────────────────────────────────────────────────────────────
id               PK. 자동 증가
nickname         클랜에서 쓰는 닉네임 (UNIQUE). 회원가입 시 연동 키로 사용됨
memo             운영진 전용 메모 (자유 텍스트)
birth_year       출생 연도 (옛날 방식, birth_date로 대체됨)
birth_date       생년월일 (DATE 타입. birth_year보다 정확)
gender           성별. 'M' / 'F' / NULL
main_line        주 포지션. 'TOP' / 'JG' / 'MID' / 'ADC' / 'SUP'
sub_line         부 포지션 (main_line과 같은 값 범위)
position         클랜 내 직책. '클랜원' / '수습' / '운영진' 등
status           활동 상태. 'active' / 'inactive' / 'banned' 등
status_note      상태 사유 (예: 군입대, 개인 사정 등)
total_points     누적 포인트 합계 (point_logs.points 합산과 항상 동기화됨)
created_at       클랜 가입일 (등록 시각)
promoted_at      클랜원 승격일 (수습 → 클랜원이 된 날짜)
withdrew_at      탈퇴일 (DATE 타입)
last_achieved_at 가장 최근 활동 달성일.
                 '칼바람 4판 or 협곡 3판 이상' 조건을 마지막으로 채운 날.
                 이 날짜 이후 다시 조건을 채우면 갱신됨.
                 판수 미달 여부를 판단하는 기준점으로 사용됨.

──────────────────────────────────────────────────────────────
■ accounts  (Riot 게임 계정. 클랜원 1명이 여러 계정 보유 가능)
──────────────────────────────────────────────────────────────
id               PK
member_id        FK → members.id (클랜원)
game_name        롤 인게임 이름 (예: 전창민)
tag_line         Riot ID 태그 (예: KR1). game_name + tag_line 조합이 UNIQUE
puuid            Riot API에서 발급하는 고유 식별자 (전적 조회에 사용)
is_main          1이면 본계정. 0이면 부계정. 클랜원 당 본계정 1개만 있어야 함
last_match_id    마지막으로 동기화한 매치 ID (중복 조회 방지)
last_played_at   마지막 게임 플레이 시각
games_2w         최근 2주간 총 게임 수 (주기적으로 Riot API 동기화)
ranked_games_2w  최근 2주간 랭크 게임 수
games_total      전체 누적 게임 수 (동기화 기준)
last_synced_at   마지막으로 솔랭 티어를 동기화한 시각
solo_tier        솔랭 티어. 'IRON' / 'BRONZE' / ... / 'CHALLENGER' / NULL
solo_rank        솔랭 단계. 'I' / 'II' / 'III' / 'IV' (마스터 이상은 NULL)
solo_lp          솔랭 LP
created_at       계정 등록 시각

──────────────────────────────────────────────────────────────
■ users  (로그인 계정. members와 1:1 연동)
──────────────────────────────────────────────────────────────
id               PK
username         로그인 아이디 (UNIQUE)
password         scrypt 해시된 비밀번호. '{salt_hex}:{hash_hex}' 형식으로 저장
nickname         화면에 표시되는 이름 (members.nickname과 같게 설정하는 게 일반적)
role             권한. 'admin' / 'subadmin' / 'member' / 'captain'
member_id        FK → members.id. 이 계정이 연동된 클랜원. NULL이면 미연동
                 UNIQUE 제약으로 클랜원 1명당 계정 1개만 연동 가능
scrim_only       1이면 내전 전용 관람 계정. /scrim 페이지만 접근 가능
status           'active' (정상) / 'pending' (가입 승인 대기)
created_at       계정 생성 시각

──────────────────────────────────────────────────────────────
■ parties  (파티 모집 공고)
──────────────────────────────────────────────────────────────
id               PK
mode             게임 모드. 'aram' / 'normal' / 'flex' / 'solo' / 'scrim'
max_size         최대 참가 인원. solo=2, 나머지=5 (고정)
status           'open' (모집 중) / 'ended' (파티 펑/종료)
host_user_id     FK → users.id. 파티를 만든 운영진 계정
host_nickname    방장 닉네임 (표시용 스냅샷. users와 별개로 저장)
note             파티 메모 (예: "노말 캐주얼하게", "탑미드구함" 등)
start_at         시작 예정 시각. NULL이면 미정
created_at       파티 생성 시각
ended_at         파티 종료(펑) 시각. NULL이면 아직 열려 있음

──────────────────────────────────────────────────────────────
■ party_participants  (파티 현재 참가자 목록)
──────────────────────────────────────────────────────────────
id               PK
party_id         FK → parties.id
user_id          FK → users.id. NULL이면 운영진이 수기로 입력한 닉네임
nickname         인게임 닉네임 (표시용). user_id가 NULL일 때도 이 값으로 식별
line             선호 라인 (예: 'TOP' 또는 'TOP,JG' 처럼 2개까지 콤마 구분)
is_waiting       1이면 정원 초과로 대기 중인 참가자
joined_at        참가 시각

──────────────────────────────────────────────────────────────
■ party_participant_history  (파티 참가자 변경 이력)
──────────────────────────────────────────────────────────────
id               PK
party_id         FK → parties.id
nickname         참가했던 인게임 닉네임
added_at         이 닉네임이 명단에 추가된 시각
※ 파티가 펑될 때 이 테이블에 기록된 모든 닉네임 대상으로 전적을 조회해
   포인트를 자동 지급한다. 중간에 나갔다 들어온 사람도 여기 남는다.

──────────────────────────────────────────────────────────────
■ point_logs  (포인트 지급 이력)
──────────────────────────────────────────────────────────────
id               PK
member_id        FK → members.id. 포인트를 받은 클랜원
points           지급 포인트 (음수 가능. 0이면 판수만 기록)
type             포인트 종류
                   'aram'          칼바람 게임
                   'normal'        일반/소환사의 협곡 게임
                   'flex'          자유 랭크 게임
                   'solo'          솔랭 게임
                   'scrim'         내전
                   'rookie_session' 수습 파티 참가 기록 (포인트=0)
                   'manual'        운영진 수동 지급
                   'award_error'   파티 펑 시 포인트 자동 지급 실패 기록
games            이 로그에 해당하는 게임 판수
comment          지급 사유 메모 (예: "칼바람 5판 달성 (07-15 00:12)")
given_by         FK → users.id. 지급한 운영진. NULL이면 시스템 자동 지급
ref_id           관련 레코드 ID. ref_table에 따라 가리키는 테이블이 다름
ref_table        ref_id가 가리키는 테이블. 'party' / 'scrim_match' / NULL
party_count      flex/scrim 모드에서 수습 클랜원 카운팅용 파티 참여 횟수
with_members     같이 플레이한 클랜원 닉네임 목록 (콤마 구분, 최대 500자)
created_at       포인트 지급 시각

──────────────────────────────────────────────────────────────
■ rookie_bonus_log  (수습 동반 보너스 중복 방지)
──────────────────────────────────────────────────────────────
id               PK
member_id        FK → members.id. 보너스를 받은 클랜원
rookie_member_id FK → members.id. 동반한 수습 클랜원
created_at       기록 시각
※ (member_id, rookie_member_id) UNIQUE — 같은 수습에게는 보너스 1회만 지급

──────────────────────────────────────────────────────────────
■ scrim_matches  (내전 경기 기록)
──────────────────────────────────────────────────────────────
id               PK
mode             내전 형식. 'draft' / 'blind' 등
status           'pending' (결과 미입력) / 'done' (완료) / 'cancelled'
winner_team      승리팀. 1 또는 2. 0이면 미결정
note             운영진 메모
played_at        경기 진행 시각
riot_match_id    Riot API 매치 ID. 자동 동기화된 경기에 저장됨.
                 UNIQUE — 같은 경기가 중복으로 들어오는 걸 방지
                 수동 입력 경기는 NULL

──────────────────────────────────────────────────────────────
■ scrim_participants  (내전 경기 참가자 & 스탯)
──────────────────────────────────────────────────────────────
id               PK
match_id         FK → scrim_matches.id
member_id        FK → members.id
team             소속 팀. 1 또는 2
line             플레이한 포지션
champion         사용한 챔피언 이름
kills            킬
deaths           데스
assists          어시스트
damage           가한 피해량
vision_score     시야 점수
cs               미니언 처치 수 (CS)
is_mvp           1이면 해당 경기 MVP
item0 ~ item6    착용 아이템 ID (Riot 아이템 코드 숫자)

──────────────────────────────────────────────────────────────
■ scrim_ratings  (내전 MMR)
──────────────────────────────────────────────────────────────
member_id        PK + FK → members.id (1인 1행)
mmr              내전 실력 지수. 초기값은 솔랭 티어 기반으로 설정됨
                   SILVER=100 / GOLD=200 / PLATINUM=300 / EMERALD=400 / DIAMOND+=500
updated_at       마지막 MMR 변동 시각 (자동 갱신)

──────────────────────────────────────────────────────────────
■ scrim_mmr_logs  (내전 MMR 변동 이력)
──────────────────────────────────────────────────────────────
id               PK
member_id        FK → members.id
match_id         FK → scrim_matches.id. 이 경기로 인해 MMR이 변동됨
delta            MMR 변화량 (양수=상승, 음수=하락)
mmr_after        변동 후 MMR
created_at       기록 시각
※ (member_id, match_id) UNIQUE — 경기 1개당 MMR 로그 1개

──────────────────────────────────────────────────────────────
■ scrim_recruits  (내전 모집 공고)
──────────────────────────────────────────────────────────────
id               PK
mode             모집 모드
max_size         모집 인원 상한 (기본 10명)
status           'open' (모집 중) / 'started' (경기 시작됨) / 'cancelled'
note             공지 메모 (예: "오늘 저녁 8시")
created_by       FK → users.id. 모집을 연 운영진
match_id         FK → scrim_matches.id. 이 모집으로 생성된 실제 경기. NULL이면 미시작
created_at       모집 생성 시각

──────────────────────────────────────────────────────────────
■ scrim_recruit_participants  (내전 모집 신청자)
──────────────────────────────────────────────────────────────
id               PK
recruit_id       FK → scrim_recruits.id
user_id          FK → users.id. 신청한 로그인 계정
member_id        FK → members.id. 신청한 클랜원
nickname         인게임 닉네임 (스냅샷)
line             신청 시 선택한 포지션
joined_at        신청 시각
※ (recruit_id, user_id) UNIQUE — 같은 모집에 중복 신청 불가

──────────────────────────────────────────────────────────────
■ played_with  (클랜원 간 함께 플레이한 기록)
──────────────────────────────────────────────────────────────
id               PK
member_id        FK → members.id. 기준 클랜원
with_member_id   FK → members.id. 같이 플레이한 클랜원
match_id         Riot 매치 ID (VARCHAR). 어떤 게임에서 같이 했는지 추적
win              1이면 이긴 게임, 0이면 진 게임
created_at       기록 시각
※ (member_id, with_member_id, match_id) UNIQUE — 같은 경기에서 중복 기록 방지

──────────────────────────────────────────────────────────────
id               PK

added_at         블랙리스트 등록 날짜 (DATE)
given_by         FK → users.id. 등록한 운영진. NULL이면 시스템
created_at       DB 기록 시각

──────────────────────────────────────────────────────────────
■ member_friends  (클랜원 지인 관계)

■ auction_sessions  (경매 세션)
──────────────────────────────────────────────────────────────
id               PK
status           'waiting' (대기) / 'active' (진행 중) / 'done' (완료)
current_idx      현재 경매 중인 선수의 순번 (auction_players.sort_order 기준)

line             주 포지션
champ1~champ3    주로 사용하는 챔피언 1~3순위

■ auction_players  (경매 세션 참가자)

================================================================
■ 테이블 관계 요약
================================================================

  members ──< accounts          클랜원 1명 = Riot 계정 여러 개
  members ──< scrim_participants 클랜원 1명 = 내전 경기 여러 번 참가
  members ──< scrim_ratings      클랜원 1명 = MMR 1행 (1:1)
  members ──< point_logs         클랜원 1명 = 포인트 이력 여러 개
