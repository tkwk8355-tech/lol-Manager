# 내전 MMR 체계 개편 계획

## 변경 배경
- 현재 티어 간격 200점, 판당 변동 최대 ±10으로 격차가 너무 작음
- 231경기 후에도 상위~하위 MMR 차이가 1500점에 불과
- 티어 승급에 의미감이 부족하여 체계 전면 개편 결정

---

## 1. 새 티어 구조 (500점 간격)

| 티어       | MMR 범위      |
|------------|---------------|
| 브론즈     | 0 ~ 499       |
| 실버       | 500 ~ 999     |
| 골드       | 1000 ~ 1499   |
| 플래티넘   | 1500 ~ 1999   |
| 에메랄드   | 2000 ~ 2499   |
| 다이아     | 2500 ~ 2999   |
| 마스터     | 3000+         |

---

## 2. 1판 MMR 변동 (방안2: 승패 고정 + 순위 보너스)

- 승리팀 기본 +20, 패배팀 기본 -20
- 팀 내 MVP 순위 보너스: 1등 +8 / 2등 +4 / 3등 0 / 4등 -4 / 5등 -8

| 순위 | 승리 최종 | 패배 최종 |
|------|-----------|-----------|
| 1등  | +28       | -12       |
| 2등  | +24       | -16       |
| 3등  | +20       | -20       |
| 4등  | +16       | -24       |
| 5등  | +12       | -28       |

### 설계 근거
- 60% 승률 30판 기준 한 티어(500점) 상승 목표 (롤 실버→골드 약 30판 기준)
- 잘하면 져도 -12로 방어 가능, 못하면 이겨도 +12만 획득 → 개인 퍼포먼스 반영

---

## 3. 기존 데이터 마이그레이션 (확정: 2배)

### 방법
기존 내전 MMR을 2배 변환 (상대 순위 보존)
- 티어 간격은 500점 유지 → 변환 후 기존보다 티어가 낮게 표시될 수 있음 (예: 기존 마스터 1200 → 2400 에메랄드)

```sql
-- scripts/migrate-scrim-mmr-x2.sql
CREATE TABLE IF NOT EXISTS scrim_ratings_backup_x2 AS SELECT * FROM scrim_ratings;
UPDATE scrim_ratings SET mmr = GREATEST(0, mmr * 2), updated_at = NOW();
```

- scrim_mmr_logs 과거 기록은 변경하지 않음 (참고용 보존)

## 4. 코드 수정 내역 (반영 완료)

1. lib/scrim.ts
   - mmrToScrimTier() 500점 간격으로 변경
   - soloBadgeToInitialMmr() 초기값 × 2 (브론즈 이하 200 / 실버 400 / 골드 700 / 플래 900 / 에메 1100 / 다이아+ 1300)
   - SCRIM_MMR_WIN_BASE = 20 추가, SCRIM_MMR_DELTA [10,5,0,-5,-10] → [8,4,0,-4,-8]
   - calcMmrDeltas()가 승패 기본점수 + 순위 보너스를 합산해서 반환

2. lib/syncScrim.ts (자동 동기화), app/api/scrim/match/resync/route.ts (소급)
   - 기존 "승 +10 / 승MVP +20 / 패 -10 / 패MVP 0" → calcMmrDeltas() 사용으로 통일
   - syncScrim의 MVP 계산에 시야점수(visionScore) 전달 누락 수정 (resync와 동일하게)

3. DB 마이그레이션: scripts/migrate-scrim-mmr-x2.sql

## 5. 팀 생성 변경 (app/api/scrim/balance/route.ts)

- 기존: 무작위 10000회 셔플 후 차이 200 이내 조합 중 무작위 선택
- 변경: 가능한 조합 252가지를 전부 계산 → 점수 차이가 작은 순으로 서로 다른 후보를 반환 (응답의 candidates, 기본 3개)
  - 블루/레드만 바뀐 같은 구성은 하나로 취급, 점수차가 같으면 순서 무작위
  - 내전 페이지(app/scrim/page.tsx)는 API를 3번 부르던 방식 → 1번 호출해서 후보 3개를 받는 방식으로 변경
  - 2단계(override 없이 재시도)로 만들어진 경우 라인 배정도 같은 기준으로 계산 (usedOverride 값도 실제대로)

| 항목                    | 기존  | 변경  |
|-------------------------|-------|-------|
| 허용 범위(tolerance)    | 200   | 없음 (최소 차이 조합) |
| 라인 보정 (ALL/미지정)  | -150  | -300  |
| 라인 보정 (명시 부라인) | -300  | -600  |
| 팀1 가산점              | +50   | +100  |

## 6. 결정 사항

- MMR 하한선: 0점 (GREATEST(0, mmr+delta) 유지)
- MVP 산정: 서폿 포함 전 라인 동일 가중치 그대로 사용 (KDA 0.25 / 딜 0.20 / CS 0.05 / KP 0.35 / 시야 0.15)
